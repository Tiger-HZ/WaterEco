# 水生态环境知识库 · 知识分类体系与元数据规范

> 版本 2026.09 ｜ 受控词表文件：`taxonomy.json` ｜ 标注引擎：`annotate.py`
> 设计基准：杭州市生态环境局水生态环境处法定职责 + 国家/浙江省/杭州市三级政策文件体系

---

## 一、为什么要重构分类体系

**改造前的状况（实测）**：

| 问题 | 实测数据 |
|---|---|
| 分类维度单一 | 仅 `category` 一个维度（policy/standard/tech/management/basin_eng/literature/intl_region），**无法体现"总氮""底栖""溢流"等业务子领域** |
| 文号缺失 | `doc_no` 覆盖 **1.4%**（5519 条仅 78 条）—— 政策法规最关键的元数据 |
| 文件层级缺失 | `content_type` 覆盖 **4.9%** |
| 时效性缺失 | `status` 覆盖 **4.3%** —— 无法判断文件是否现行有效 |
| 归口部门失真 | `department` **87.5% 为"其他"** |
| 地域失衡 | 国际 69%、全国 30%、**浙江 0.45%、杭州 0.27%** —— 本地业务几乎空白 |

**改造后**：以"业务域"为一级维度，构建 6 个相互独立、可交叉筛选的维度，并由 `annotate.py` 自动标注。

## 二、分类体系总览（6 个维度）

```
条目
 ├── ① 业务域 topic        [23 个受控值]  ← 核心维度，对齐处室职责
 ├── ② 文件层级 level      [18 个受控值]  ← 决定权威性与排序
 ├── ③ 地域 region         [6 个受控值]   ← 全国/浙江/杭州/长三角/流域/国际
 ├── ④ 归口部门 department [11 个受控值]
 ├── ⑤ 重点水体 waterbody  [14 个受控值]  ← 钱塘江/苕溪/运河/千岛湖/杭州湾…
 └── ⑥ 时效 status         [4 个受控值]   ← 有效/已修订/已废止/待核
```

## 四、② 文件层级（18 个，权威性排序）

```
法律 → 行政法规 → 部门规章 → 规范性文件 → 国家标准 → 行业标准
→ 地方性法规 → 省政府规章 → 地方政府规章 → 地方标准
→ 国家规划 → 省级规划 → 市级规划 → 技术导则 → 公报报告
→ 研究文献 → 实践案例 → 资讯动态
```

**用途**：① 门户"必知必会"分层排序；② 决定 `importance` 基准分；③ 决定 `quality` 等级。

## 五、③④⑤⑥ 其余维度

**地域 region**：全国 / 浙江 / 杭州 / 长三角 / 流域 / 国际
- 识别规则：域名优先（`hangzhou.gov.cn`→杭州；`zj.gov.cn`/`zjrd.gov.cn`→浙江）+ 关键词（"淳安""余杭""临平"→杭州）
- **地域加权**：importance 计算时 杭州 +0.6、浙江 +0.4、流域 +0.3（本地文件对处室价值更高）

**归口部门 department**：生态环境 / 水利 / 住建 / 发改 / 农业农村 / 自然资源 / 卫生健康 / 市场监管 / 交通 / 应急管理 / 其他
- 识别规则：发文机关关键词 → 域名后缀（`mwr.gov.cn`→水利、`mohurd`→住建）→ 兜底"其他"

**重点水体 waterbody**：钱塘江（含富春江/新安江）/ 苕溪 / 运河 / 千岛湖 / 杭州湾 / 西湖 / 西溪 / 分水江 / 浦阳江 / 曹娥江 / 太湖
- 支撑"流域治理全景"视图与图谱流域轴

**时效 status**：有效 / 已修订 / 已废止 / 待核
- 推断规则：标题含"修正/修订/修改"→已修订；含"废止/失效/停止执行"→已废止；法规标准类默认"有效"

## 六、元数据字段规范

| 字段 | 中文 | 必填 | 来源 | 说明 |
|---|---|---|---|---|
| `title` | 标题 | ✅ | 采集 | 清洗后完整标题 |
| `url` | 原文链接 | ✅ | 采集 | **必须真实可达**；抓不到原文时填官方栏目页并在 note 说明 |
| `cid` | 内容指纹 | ✅ | 计算 | sha1，用于外置正文 `kb/full/<cid>.txt` |
| `_ev` | 事件指纹 | ✅ | 计算 | 规范化全标题 sha1，用于去重 |
| `topic` | **业务域** | 自动 | annotate | 多值，最多 3 个 |
| `topic_conf` | 标注置信度 | 自动 | annotate | high/low，供人工复核聚焦 |
| `content_type` | 文件层级 | 自动 | annotate | 18 类受控值 |
| `doc_no` | **文号** | 自动 | annotate | 12 条正则；**抽不到留空，绝不编造** |
| `department` | 归口部门 | 自动 | annotate | 11 类受控值 |
| `region` | 地域 | 自动 | annotate | 6 类受控值 |
| `waterbody` | 重点水体 | 自动 | annotate | 多值 |
| `status` | 时效 | 自动 | annotate | 4 类受控值 |
| `summary` | 摘要 | 采集/生成 | — | 80–130 字 |
| `importance` | 重要性 | 自动 | annotate | 0–10，层级基准 + 地域加权 |
| `quality` | 质量 | 自动 | annotate | A/B/C |
| `kg_terms` | 图谱术语 | 自动 | kg_build | **已剔除学科分类词** |
| `date` / `effective_date` | 发布/施行日期 | 采集 | crawl_sites | URL 日期还原兜底 |

## 七、自动标注方法（三层判定）

```
第 0 层：权威映射（人工确认，优先级最高）
        taxonomy.override —— 48 条规则，覆盖旗舰法律与综合文件
        例：《中华人民共和国水污染防治法》→ [水环境质量管理, 入河排污口监管, 城镇污水处理与提质增效, 制度机制与法治保障]
        意义：大法内容过于综合，词表匹配会漏标/误标；人工映射保证"该归的一定归对"

第 1 层：core 核心词命中（自动，可靠）
        命中任一 core 词 且 得分 ≥ 2.0 → 判定该业务域
        词源：中文 110 + 英文 73 个高区分度专业术语（"底栖""总氮""入河排污口""macroinvertebrate"）

第 2 层：辅助词加权（自动，需强证据）
        · 无 core 命中时，辅助词总分 ≥ 6.0 才例外入选
        · 仅正文命中 core 时，需 ≥2 个不同 core 词（防止长文泛词误标）
```

**打分层级权重**（标题最强）：

| 位置 | core 词中文 | core 词英文 | 辅助词中文 | 辅助词英文 |
|---|---|---|---|---|
| 标题 | 4.0 | 3.2 | 1.4 | 1.0 |
| 摘要 | 1.6 | 1.2 | 0.5 | 0.4 |
| 正文 | 0.9 | 0.6 | 0.25 | 0.2 |

**关键工程细节**：
1. **必须读外置正文** —— 长正文存于 `kb/full/<cid>.txt`，kb.json 中无 `content`。不读正文会导致覆盖率严重偏低（这是首轮实测 87% 未标注的真正原因）。
2. **中英双语** —— 库内学术文献标题多为英文，纯中文词表无法匹配。
3. **词边界匹配** —— 英文用 `\b…\b`，避免 `bay` 命中 `Bayesian`。
4. **幂等** —— 可反复运行，结果稳定。

## 八、质量与重要性算法

**重要性 importance（0–10）**：
```
importance = 层级基准分 + 地域加权 + 政策加权 + 水相关度加权
  层级基准：法律 10.0｜行政法规 9.5｜国家标准 9.2｜部门规章/国家规划 9.0
            地方性法规 8.8｜行业标准 8.5｜规范文件 8.3｜… ｜资讯动态 4.5
  地域加权：杭州 +0.6 ｜ 浙江 +0.4 ｜ 流域 +0.3
  政策加权：中央/国办/主席令/生态环境法典 +0.3
  水相关度：water_rel × 0.3
```

**质量 quality**：
- **A**：国家部委或省市人大/政府权威发布的法规、标准、规划、公报（或标题含主席令/国务院令/部令/〔年〕号文号）
- **B**：厅局级发布、地方实践、省级规划、技术导则、公报报告
- **C**：动态简讯、一般资讯、普刊文献、转载类

## 九、标注质量保障

| 机制 | 做法 |
|---|---|
| 保守原则 | 证据不足**留空**而非猜测（宁缺毋滥） |
| 置信度分级 | `topic_conf` 标 high/low，人工只复核 low |
| 抽样核对 | `--report` 输出各域抽样条目（标题+文号+层级+地域+分数），便于逐条验证 |
| 权威映射 | 旗舰文件由人工确认后固定，避免自动误标 |
| 词表可维护 | 全部词条在 `taxonomy.json`，改词表无需改代码 |
| 回归验证 | 改词表后重跑 `annotate.py --dry --report` 对比分布变化 |

**演进记录（本轮实测迭代）**：
1. 初版纯中文词表 → 87% 未标注（学术文献为英文）
2. 加英文词表 + 长度归一 → 误标"制度机制"227 条（泛词污染）
3. 引入 core 词分层 → 旗舰法律反而漏标（内容太综合）
4. **加权威映射表 + 标题/正文命中分离** → 抽样 40 条命中 22 条且**准确率显著提升**（旗舰法律全部正确归类）

## 十、受控词表维护规程

1. **新增业务域**：职责扩展时（如新设"新污染物管控"）在 `taxonomy.json` 的 `topic.values` 追加，含 `id/zh/duty/keywords/core` 五要素
2. **新增词条**：直接追加到对应域 `keywords`；高区分度术语同步加入 `core`
3. **新增权威映射**：旗舰文件或反复误标的条目，加入 `override.map`
4. **改后必做**：`python3 annotate.py --dry --report` 对比分布 → 抽样核对 → 无回归再正式写回
5. **前端同步**：门户 `index.html` 的业务域选项由 `patch_index_taxonomy.py` 从 `taxonomy.json` 生成，改词表后**必须重跑该脚本**
