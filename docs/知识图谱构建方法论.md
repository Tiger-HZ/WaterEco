# 水生态环境知识库 · 知识图谱构建方法论

> 版本 2026.09 ｜ Schema：`kg_schema.json` ｜ 构建器：`kg_build.py` ｜ 产物：`kb/graph.json`

---

## 一、为什么必须重构（实测问题）

**改造前**：图谱依赖 `kg_terms` 字段（由 `enrich_kg.py` 从关键词频次生成）。

| 实测问题 | 数据 |
|---|---|
| 混入学科分类词 | 最高频"实体"竟然是 **Environmental science（556）、Biology（265）、Chemistry（170）、Computer science（154）** —— 这些是 OpenAlex 的**学科分类**，不是知识实体 |
| 无类型概念 | 4939 个术语平铺，分不清"是水体、机构、还是污染物" |
| 无关系语义 | 只能按共现连线，说不出"依据""监管""适用" |
| 噪声实体 | 《Quality in Sport》类无关文献贡献的术语混入 |

**结论**：`kg_terms` 只是"关键词云"，不构成知识图谱。必须重建为**有类型、有关系、可推理**的结构化网络。

## 二、实体类型（9 类）

| 类型 | 中文 | 说明 | 规模 | 示例 |
|---|---|---|---|---|
| `waterbody` | 水体/流域 | 受监管水体 | 19 | 钱塘江、千岛湖、杭州湾、苕溪、京杭运河 |
| `regulation` | 政策法规与标准 | 文件类记录本身 | 动态 | 《生态环境法典》、GB 3838、浙江省水污染防治条例 |
| `org` | 机构 | 发布/监管主体 | 24 | 生态环境部、浙江省人大、杭州市生态环境局 |
| `pollutant` | 污染物与水质指标 | 管控目标物质 | 27 | 总氮、总磷、氨氮、COD、叶绿素a、六价铬、新污染物 |
| `indicator` | 评价指标/考核口径 | 评价指标 | 17 | Ⅲ类水质比例、生物完整性指数(IBI)、总氮削减率、再生水利用率 |
| `tech` | 技术/工艺/方法 | 治理监测技术 | 24 | 人工湿地、生态缓冲带、MBR、A²O、反硝化深床滤池、eDNA 监测 |
| `facility` | 工程设施 | 物理载体 | 14 | 污水处理厂、入河排污口、排水管网、水质自动监测站 |
| `action` | 行动/专项/机制 | 治理行动 | 19 | 五水共治、污水零直排区、美丽河湖建设、查测溯治、河湖长制 |
| `issue` | 问题（隐含实体） | 用于 addresses 关系 | 20 | 返黑返臭、总氮超标、富营养化、溢流污染、底栖生物退化 |

> **`issue` 类型的设计用意**：把"问题"也建成节点，才能回答"**哪些文件在解决哪类问题**"、
> "**哪类问题治理文件最少**"（缺口检查）。

## 三、关系类型（11 类）

| 关系 | 中文 | 起止 | 依据 | 权重 |
|---|---|---|---|---|
| `issued_by` | 由…发布 | regulation → org | 发文机关字段/来源 | 3 |
| `based_on` | 制定依据 | regulation → regulation | 正文"依据《X》" | 4 |
| `implements` | 贯彻落实 | regulation → regulation/action | 标题/正文"为落实X" | 3 |
| `revises` | 修订/替代 | regulation → regulation | 标题"修正/修订/替代" | 3 |
| `applies_to` | 适用范围 | regulation → waterbody/region | 词表命中（标题命中记 4） | 3–4 |
| `targets` | 管控对象 | regulation/tech → pollutant/facility | 词表命中 | 3 |
| `addresses` | 解决问题 | regulation/action → issue | 词表命中 | 3 |
| `monitors` | 监测/评价 | tech/facility → indicator | 词表命中 | 2 |
| `applied_in` | 落地实践 | tech/action → region | 词表命中 | 2 |
| `co_occurs` | 同文共现 | 任意 ↔ 任意 | 同文件共现 | 2（弱） |

**设计原则**：每条边都**可解释**（能说出"凭什么连"）。显式关系（发布/依据/修订）权重高，
共现关系权重低且需通过剪枝阈值，避免图谱被弱关联噪声淹没。

## 四、构建流程（四步）

```
① 建 regulation 节点
   仅对"文件类"记录建节点（content_type ∈ 法律/行政法规/规章/标准/规划/规划/导则/公报）
   —— 研究文献、资讯动态**不入图**，避免学术噪声淹没业务图谱

② 抽实体（词表精确匹配，长词优先）
   实体词典来自 kg_schema.json；按长度降序匹配，防止"总氮"被"氮"抢先命中
   匹配范围：标题 + 摘要 + 外置正文（kb/full/<cid>.txt 前 4000 字）

③ 建关系（规则驱动）
   · 发文机关 → issued_by
   · 依据链正则"依据《X》"→ based_on（X 须在库内存在同名文件，避免虚链）
   · 修订标题 → revises
   · 词表命中 → applies_to / targets / addresses / monitors
   · 同文件共现 → co_occurs（弱连接）

④ 剪枝与输出
   · 只保留 regulation 节点与直接相连实体（保证图谱以业务文件为中心）
   · 度 <3 的节点仅保留非 co_occurs 边
   · 输出 nodes / edges / stats
```

## 六、四类分析应用

### 6.1 政策沿革追溯
以 `regulation` 为轴，沿 `based_on` / `revises` 回溯，形成沿革链：
```
《生态环境法典》(2026)          ← 上位法
   ↑ based_on
《浙江省水污染防治条例》(2026 第四次修正)
   ↑ based_on
《杭州市河湖保护治理条例》(2026-08-28 通过)
```
**用法**：领导问"某要求依据是什么"，可一键回溯到上位法。

### 6.2 流域治理全景
以 `waterbody` 为轴，聚合 `applies_to` 的法规 + `targets` 的污染物 + `applied_in` 的技术行动：
```
钱塘江流域 ──► 适用法规 N 部 ──► 管控 总氮/总磷/氨氮 ──► 技术 生态缓冲带/人工湿地
```
**用法**：编制流域专项方案时，快速掌握"已有哪些依据、管什么、用什么技术"。

### 6.3 政策缺口检查（对处室最有价值）
**方法**：遍历 23 个业务域，检查每个域下 `regulation` 节点数量。

| 判定 | 含义 | 处置 |
|---|---|---|
| 域下有法规/标准 | 依据充分 | — |
| 域下仅规范性文件 | 依据层级偏低 | 补充上位法 |
| **域下为空** | **该领域政策依据缺失** | **列为定向采集任务** |

> 例：本轮据此发现"**工业与园区水污染源监管**"无独立业务域（行业排放标准无处归）；
> 以及"**底栖/生物完整性评价**"仅有行业标准、缺地方实施细则 —— 均为下一轮采集重点。

### 6.4 治理热点识别
按 `issue` 节点度数 + 时间分布，识别当前治理焦点：
频次高且近期文件密集 → 当前热点（如"返黑返臭""总氮超标"）；
度数低但被上级文件反复点名 → 潜在待办（如"底栖生物退化"）。

## 七、技术实现要点

| 要点 | 做法 | 原因 |
|---|---|---|
| 节点 ID | `类型前缀_sha1(名称)[:10]` | 稳定可复现，同名实体自动合并 |
| 长词优先匹配 | 词表按长度降序排序后匹配 | 防止短词抢先（"总氮"vs"氮"） |
| 依据链防虚链 | `based_on` 目标须在库内存在同名文件 | 避免指向库外不存在文件 |
| 剪枝 | 度数阈值 + 剔除纯共现孤立节点 | 图谱规模可控、可读 |
| 外置正文读取 | 标题+摘要不足时回落读 `kb/full/<cid>.txt` | 长正文关系（依据/技术）多在正文中 |
| 幂等 | 每次全量重建，不增量叠加 | 避免历史误差累积 |

**输出格式**：
```json
{
  "nodes": [{"id":"wb_1a2b3c4d5e","name":"钱塘江","type":"waterbody","cnt":7}],
  "edges": [{"s":"reg_xxx","t":"wb_1a2b","rel":"applies_to","w":4}],
  "stats": {"nodes":234,"edges":364,"by_type":{...},"by_rel":{...}},
  "schema_version": "2026.09"
}
```

**门户呈现**：关系图谱页优先加载 `kb/graph.json`，按实体类型着色，
节点标签形如「水体·钱塘江」「污染物·总氮」「机构·生态环境部」，支持拖拽缩放与点击查看；
加载失败自动回退原有聚合可视化（不影响可用性）。

## 八、局限与后续演进

| 局限 | 现状 | 演进方向 |
|---|---|---|
| 关系抽取以词表为主 | 精准但召回有限 | 引入"依据/落实"句式模板扩充召回 |
| 断面/监测点未入图 | schema 已预留概念 | 接入地表水断面名录后建 `section` 类型 |
| 时间维度未建模 | 仅有 date | 增加"版本时间线"，支撑沿革可视化 |
| 未做实体消歧 | 同名不同指未处理 | 加机构规范化表（如"生态环境部"与"环境保护部"的历史关系） |
| 度数统计口径 | `cnt` 为出现次数 | 增加"文件覆盖数"与"跨域连接度"双指标 |
