# 知识类别体系 与 法规原文校核机制

> 版本 2026.09 ｜ 配置：`kclass.json`（16 类知识类别）｜ `law_sources.json`（法规原文权威出处）
> 执行件：`annotate.py`（类别标注）｜ `crawl_law.py`（法规原文抓取与校核）｜ `patch_index_kclass.py`（门户同步）

---

## 一、为什么扩展知识类别

**原状况**：`category` 只有 7 类（政策法规 / 标准规范 / 流域治理与工程 / 管理机制与实践 / 技术产品 / 研究文献 / 国际与区域经验），
**覆盖不了一般与常见的知识类别** —— 报告、案例、专家、机构、数据、术语、科普、讲话等无处可归。

**现方案**：新建 **16 类「知识类别」(kclass)**，参考"报告研究类 / 教育科普类 / 概念术语类 / 科研文献类 / 案例实践类 /
技术产品类 / 新闻媒体类 / 机构信息类 / 数据资源类 / 政策法规类 / 人物专家类 / 重要讲说类"体系，
结合水生态环境业务增减而成。

## 二、16 类知识类别

| # | 类别 | 说明 | 判定依据 |
|---|---|---|---|
| 1 | **政策法规** | 法律、行政法规、部门规章、规范性文件、地方性法规与政府规章 | 文件层级精确匹配 |
| 2 | **标准规范** | 国家标准、行业标准、地方标准、技术导则与规程 | 文件层级精确匹配 |
| 3 | **规划与报告** | 国家/省/市规划、公报、评估报告、质量月报年报、执法检查报告 | 层级 + "规划/公报/评估报告" |
| 4 | **管理机制** | 管理制度、工作机制、考核办法、行动计划、实施方案（非法规类） | "管理办法/工作机制/实施方案/指导意见" |
| 5 | **案例实践** | 各地治理做法、典型经验、试点示范、优秀案例 | "经验/做法/示范/试点/典型/模式/借鉴" |
| 6 | **技术产品** | 治理技术、工艺、装备、产品与材料 | "技术/工艺/装备/人工湿地/缓冲带/膜/滤池" |
| 7 | **流域治理与工程** | 流域治理方案、工程建设、河道整治、修复工程 | "工程/治理方案/河道整治/清淤/水系连通/岸线" |
| 8 | **科研文献** | 学术论文、研究报告、综述 | DOI/OpenAlex 链接 或 层级=研究文献 |
| 9 | **数据资源** | 数据集、统计资料、监测数据、指标口径 | "数据集/统计数据/监测数据/名录/数据库" |
| 10 | **概念术语** | 术语定义、名词解释、标准术语、概念辨析 | "术语/定义/名词解释/释义" |
| 11 | **教育科普** | 科普文章、一图读懂、问答、宣传解读 | "科普/一图读懂/图说/问答/明白纸" |
| 12 | **重要讲话** | 领导讲话、署名文章、致辞、访谈、发布会实录 | "讲话/署名文章/致辞/访谈/答记者问" |
| 13 | **机构信息** | 机构职能、单位简介、科研院所与团队 | "机构/职能/研究院/研究所/重点实验室/团队" |
| 14 | **人物专家** | 专家、学者、标准起草人、学科带头人（公开署名信息） | "专家/学者/教授/院士/起草人/编制组" |
| 15 | **新闻媒体** | 工作动态、简讯、媒体报道 | 层级=资讯动态 |
| 16 | **其他** | 暂未归类 | 兜底 |

**判定顺序**（`annotate.py` 的四步）：
```
① DOI / OpenAlex / EuropePMC 链接 → 科研文献（最可靠，避免英文文献被误归资讯）
② 文件层级精确匹配 → 政策法规 / 标准规范 / 规划与报告 / 新闻媒体
③ 标题与摘要特征词匹配 → 管理机制 / 案例实践 / 技术产品 / 流域治理与工程 /
   数据资源 / 概念术语 / 教育科普 / 重要讲话 / 机构信息 / 人物专家
④ 多类命中时按 order 优先级取最靠前者（政策 > 标准 > 规划 > 管理 > 案例 > 技术 …）
```

## 三、知识类别与业务域是**两个正交维度**

| 维度 | 回答的问题 | 用途 |
|---|---|---|
| **业务域 topic**（23 个） | 这条知识**属于哪个业务领域**？（总氮管控？饮用水源？入河排污口？） | 按职责检索、政策缺口检查 |
| **知识类别 kclass**（16 类） | 这条知识**是什么形态**？（法规？标准？案例？文献？数据？） | 按知识形态检索、内容配比控制 |

**组合威力**：可回答"总氮管控领域有哪些**标准**"、"饮用水源领域有哪些**案例**"、
"入河排污口领域的**法规**是否齐备" —— 单维度做不到。

门户已支持：**按业务域**导航（23 域计数）+ **按知识类别**导航（16 类计数），二者可叠加筛选。

## 四、法规原文校核机制（解决"有链接没原文"）

### 4.1 问题（用户指出）
《中华人民共和国水污染防治法》库内**有链接但无原文** —— 链接指向通知/简介类页面，不是法规全文。
排查发现这不是孤例：**长江保护法指向英文版、海洋环境保护法指向繁体代理域、水法指向繁体代理页**。

### 4.2 为什么必须要"全文"
法规/规章类条目若无全文，则：无法核验条文、无法引用具体条款、无法做依据链与图谱分析 —— **等于没有**。

### 4.3 校核判据（`crawl_law.py` 的 `law_quality`）
```
判定为"法规全文"须同时满足：
  ① 含"第一条"（法规体例的硬标志）
  ② 不同条文数 ≥ 15（排除只有摘录的页面）
  ③ 纯文本 ≥ 3000 字（排除通知/解读/新闻页）
不满足 → 视为非全文 → 标记 origin_status="暂未收录"，note 写明原因，**绝不用通知页冒充原文**
```

### 4.4 权威出处映射（`law_sources.json`，人工核实 + 实测）
| 法律 | 出处 | 实测 |
|---|---|---|
| 中华人民共和国水污染防治法 | 浙江省人民政府·法律法规库 | **15517 字 / 103 条** |
| 中华人民共和国长江保护法 | 全国人大信息中心·国家法律法规数据库（文本版） | **14609 字 / 96 条** |
| 中华人民共和国海洋环境保护法 | 人民日报（法律全文发布版） | **43362 字 / 124 条** |
| 中华人民共和国水法 | 政府门户转载全文（2016 修正版） | **13145 字 / 82 条** |
| 中华人民共和国防洪法 | 政府门户附件全文 | **10161 字 / 65 条** |
| 中华人民共和国湿地保护法 | 人大法律库 PDF 版 | 待补（PDF 为图文版，解析不全） |

**工具链支持三种格式**：HTML 正文页、PDF（pypdf 解析）、DOCX（python-docx 解析）。

### 4.5 机制（三道）
1. **抓取修复**：`crawl_law.py --apply` 按映射表抓取 → 严格校验 → 校验通过才写入
2. **全库扫描**：`crawl_law.py --scan` 对全部法规类条目检查"是否为全文"，产出**缺全文清单**（即真实缺口）
3. **显式标注**：不合格条目一律标 `origin_status="暂未收录"` 并在备注说明原因，门户可见可追踪

### 4.6 本轮成果
- **修复 5 部旗舰法律**：水污染防治法、长江保护法、海洋环境保护法、水法、防洪法 —— 均已入库完整全文
- **如实标记 2 条待补**：环境保护法、湿地保护法（未找到可靠全文源；已标"暂未收录"并写明原因）
- **待检索 13 条**（`law_sources.json` 的 `pending_search`）：渔业法、太湖流域管理条例、
  城镇排水与污水处理条例、地下水管理条例、排污许可管理条例、河道管理条例、
  浙江省水污染防治条例、浙江省饮用水水源保护条例、杭州市河湖保护治理条例等

### 4.7 后续流程
```
缺全文清单 → 逐条检索权威出处（人大法律库 / 浙江省法规库 / 政府门户全文页 / 公报）
         → 填入 law_sources.json（含出处、核实日期、实测证据）
         → crawl_law.py --apply 抓取校验入库
         → 仍找不到 → 保持"暂未收录"并在门户显式标注
```
